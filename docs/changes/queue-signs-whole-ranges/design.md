# Queue signs whole ranges: design

## Approach

The [proposal](proposal.md) states the scope and the [draft decision record](adr.md) gives the reasons. The [delta specification](specs/queue-signs-whole-ranges/spec.md) states the behavior in role terms. This file maps each requirement to the command, flags, and strings that implement it.

A range request is a head request with one more field. The head request's receipt check, publish refusal, claim, lock, pinned signing settings, and push line all apply unchanged. What differs is the set of commits the one `jj sign` run names, the view before the key, and the check after the run.

## Structure

- `store.rs`: `Request` gains kind `range` and `range: { protected, base, commits: [Identity] }`. `protected` is the remote-tracking ref name, `base` its commit id at request time, and `commits` the identities oldest first. `head` holds the last entry, so every field that reads `head` keeps working. A record without `range` reads as before.
- `repo.rs`: `range(base, head)` runs `git rev-list --reverse --topo-order <base>..<head>`. `head_at(commit)` reads one commit's identity and signature. `sign(commits, signing)` builds `commit_id("<id>")` for every commit, joined with `|`, and refuses first while any config file jj reads, conditional scopes at any depth included, defines an alias that starts with `commit_id(`. It writes the named identities for the shim, pins `signing.backends.gpg.program` to the shim's wrapper for the run, and reads the shim's state after it: a refusal returns `SignOutcome::Refused`. Then `signed_exactly` compares the commits the run kept under `refs/jj/keep/*` with the named set and prints a note on a difference. Nothing is reverted. Every git and jj process the queue starts runs with `GIT_NO_REPLACE_OBJECTS=1`.
- `shim.rs`: `Run::create` writes one state file and one `gpg` wrapper under `<state dir>/sign-queue/shim/<pid>-<nanos>/`. The wrapper runs `rune sign gpg-shim --state <file> -- "$@"`. `run` reads the payload, parses it as a git commit object, and matches it with `rewrites` against a named commit not yet signed, with parents mapped through the signed ids the shim computed so far. A match runs the owner's program with jj's arguments and records the signed id, which is the payload with the signature as a `gpgsig` header, hashed as git does. Anything else writes the reason to the state and exits 2 before the owner's program runs, so `jj sign` fails. A call that is not a signing request goes to the owner's program unchanged.
- `ceremony.rs`: `range_view` and `range_lines` render the range, the count, one line per author, and one line per commit. Every bookmark, path, author, message line, coverage field, and reason the views print passes through the hook dispatcher's `visible`, so a control, ANSI, or Unicode format character shows as `\xNN` or `\u{NNNN}`. `sign_with_retry` takes the commits to name and, for a range, the range whose base `base_holds` checks before every attempt, and records a refusal at the key as a failure.
- `mod.rs`: `queue_range`, `sign_range`, `verify_signed_range`, `check_signatures`, `range_holds`, `head_matches`, `identities_match`, the same escape in `rune sign show`, and the `moved` and rewritten cases in `derive`.
- `src/cli/mod.rs`: `--range` on `rune sign queue`, which needs the bookmark and conflicts with `--prune`. The hidden `rune sign gpg-shim --state <file> -- <gpg arguments>`.

## Commands

| Role | Command |
| --- | --- |
| A session queues a range | `rune sign queue <bookmark> --range --receipt <file> [--repo <dir>] [--json]` |
| The queue lists the range | `git rev-list --reverse --topo-order refs/remotes/origin/<main\|master\|trunk>..<head>` |
| The owner sees the range and answers | `rune sign next`, `rune sign all`, `rune sign show <bookmark>`. The answer comes from `/dev/tty`, or from the file `RUNE_SIGN_TTY` names in tests |
| The signer signs the range | `jj sign -r 'commit_id("<id>") \| commit_id("<id>")'` with the head request's pinned `--config` overrides, and `signing.backends.gpg.program` pinned to the run's wrapper |
| The signature checks the commit | `rune sign gpg-shim --state <file> -- <gpg arguments>`, run by the wrapper for every payload. The state file holds the owner's program, the named identities, and the signed ids so far |
| The signer checks each commit | `git verify-commit --raw <id>` for every commit the range lists between the base and the new head |
| The signer reads every jj config file | `$HOME/.jjconfig.toml`, `$XDG_CONFIG_HOME/jj/config.toml`, `$XDG_CONFIG_HOME/jj/conf.d/*.toml`, `/etc/jj/config.toml`, and `/etc/jj/conf.d/*.toml`, or the files `JJ_CONFIG` lists in their place, plus `jj config path --repo` and `jj config path --workspace`. `jj config list --include-overridden -T path` confirms that jj reads no other file, then `jj config list revset-aliases -T <listing>` runs last |
| The signer checks the base again | `git rev-parse refs/remotes/origin/<main\|master\|trunk>` after the answer, before every `jj sign` attempt, and after the signatures verify |
| Every repository read ignores replacement objects | `GIT_NO_REPLACE_OBJECTS=1` in the environment of every git and jj process the queue starts |
| The owner prunes a moved request | `rune sign queue --prune` |

## Messages

- `sign.range_empty`: `<bookmark> at <head> adds no commit to <protected ref>: there is nothing to sign`. `sign.head_published` as for a head request. `--json` adds `"kind": "range"` and `"commits": <n>`. The text line ends with `(<n> commits)`.
- The view has `range <protected ref> at <base>..<head>`, `commits <n>`, one `author <name> <n>` line per author, and one `<short id>  <author>  <first line>` line per commit. The prompt is `sign <n> commits on <bookmark> from <base> to <head>? [y/N]`. A decline reports `declined`.
- Stale at the key: `stale: <protected ref> moved to <short id> since the request: rebase and queue again`, or `stale: the commits between <base> and <head> changed since the request`. The listing shows `skipped: stale`.
- Failure reasons after the run: `<n> commits between <base> and <head>, the request recorded <m>`, `<short id> changed identity while signing`, `<short id>: signature from key <fingerprint> is not in KEYS`, `<short id>: signature rejected: <status>`.
- Stale after the key: `failed: stale: <protected ref> moved to <short id> since the request: rebase and queue again`, recorded as a failure because the commits are signed above a base the owner did not see.
- The alias refusal: `failed: the jj config <file> defines revset alias <name>, which redefines commit_id(): unset it before signing`, where `<name>` is `revset-aliases."<key>"`, or the same with `--scope.` in front once per level of conditional scope, as `--scope.--scope.revset-aliases."<key>"`. A file the check cannot read or parse: `failed: cannot read the jj config <file>: <error>: the alias check needs every config file`. A file jj reads that the check did not: `failed: jj reads the config file <file>, which the alias check did not: refusing to sign`.
- A moved request: list state `moved`, signer line `skipped: moved: signed at <short id>, the bookmark moved since`, and the run ends with `prune signed requests whose bookmark moved with rune sign queue --prune`.
- A rewritten request: a signed head or range request whose bookmark carries the recorded identity under a new id lists as `current` again, and the next run signs it and records the new head. A signed open or merge seal whose bookmark carries the seal's identity under a new id lists as `stale`, so it never prunes and never passes as done.
- The refusal at the key: `failed: jj sign asked the key for <short id> (change <short id>), which is not a named commit: refused before the key`, or `for an object that is not a commit (<short id>)`. The shim prints the same reason to stderr for jj. The reason carries ids only.
- The report after the run: `note: after the run, jj sign also signed <short id> (change <short id>); every signature came through the shim, so look at jj op log before you push`. A named commit without a signed rewrite reads `no signed rewrite of <short id> (change <short id>)`.

## Risks

- A range of many commits makes a long view. The view prints one line for each commit and no diff, so it stays readable at 77 commits.
- `jj sign` may rewrite descendants outside the range. `signing.behavior` is pinned to `drop`, so they lose any signature. A descendant that the queue holds keeps its identity and stays current, whether it was queued or already signed. An open or merge seal sits above its recorded head, so the same rewrite lists it as `stale`: the local bookmark now rests on an unsigned seal, and a later push would publish it, so the request never lists as done. The owner reruns the open or submit step to seal it again.
- Decision: the signature itself checks the commit. The first design compared the commits a run wrote with the named set afterwards and reverted the operation. Two races got past it. An alias guard and `jj sign` read the config at different times, so a sign-scoped `commit_id(x)` alias written between the two reads made the key sign a commit outside the set. The revert hid the commit, but the signed object stayed under `refs/jj/keep/` and a push carried it. A jj operation written during the run left two operation heads, the revert was skipped, and the request stayed current. The shim closes both: the key is asked only for a payload that is the rewrite of a named commit, whatever jj resolved the revset to and whatever the operation store holds, so there is nothing to revert. The alias guard stays as a second layer. The comparison after the run stays as a report, so the owner sees a rewrite that was not expected.
- On jj 0.46 the payload `jj sign` hands gpg is not the stored commit, so the shim cannot hold a set of hashes. jj rewrites the commit first, with a fresh committer line, and a later commit of a range names the signed rewrite of the earlier one as its parent. The shim matches the identity fields, as `signed_exactly` does, and maps parents through the signed ids it computed: the payload with the signature as a `gpgsig` header, hashed as git hashes a commit. `tests/sign_queue.rs` proves both facts against jj itself, and the tests for both races fail on the first design.
- The shim's wrapper is a shell script, because jj runs the gpg program bare and `signing.backends.gpg` has no argument setting. The script names the rune binary and the state file by absolute path.
- The alias guard reads the config files from the locations jj documents and confirms the list against the `path` keyword of `jj config list`. A file jj reads from an undocumented location whose every entry sits in a scope that is inactive for `config list` would not appear in that listing. The listing templates use the `name`, `value`, `overridden`, and `path` keywords, which `refuse_listing_aliases` checks against `template-aliases` first.
- A range head is compared by `same_commit`, which tolerates an empty recorded change id. A head request keeps the strict comparison, because jj wrote its head and recorded the change id.
