# Cursor joins run and launch: design

## Approach

Cursor joins `rune run` as a sixth tool in the existing adapter set: one `Surface::Cursor` variant, one row in each table, and one module with the argument builder and the parser. It uses the same process request, owned-argument filter, failure type, exit codes, and `hint` field as the other tools. The alternative was a generic "JSON print tool" adapter driven by config. It lost because each tool differs in prompt transport, access flags, and error shape, and the owned table is the security boundary, which config must not widen.

## Structure

- `src/cli/surface/cursor.rs`: `BOOLEAN_OPTIONS` and `OWNED_OPTIONS` hold the owned flags, including `--plugin-dir`, because a plugin can add tools. `keep_allowed` then keeps only `KEPT_OPTIONS`, `-e` and `--endpoint`, each with a plain value, and drops every other profile argument, because `cursor-agent` accepts options its help does not list and `--api-key` would put the key in `ps`. `split_option` cuts each token into the option name and its attached value: a long name ends at `=`, a short name is the first two characters, so `-xVALUE` and `-x=VALUE` both name `-x`, as commander reads them. A warning shows only that name or a position. `args` builds the argument list. `prompt_input` puts the system prompt in front of the prompt, with the clean preamble under `--clean`. `invoke` refuses an unsupported mode, sends the text on standard input, and `parse` reads the terminal record: `top_level_records` parses the whole output as one JSON value first, else one value per line, and a line that is not JSON fails the output, so a truncated error cannot leave a stale success in place. `result_object` takes the last top-level record and requires it to be a result object, so an object nested inside an error never stands in for the answer. `check_access` refuses a read-only run when the `cli-config.json` in `config_dir` sets `approvalMode` to `unrestricted`. `config_dir` resolves the directory as `cursor-agent` does, `CURSOR_CONFIG_DIR`, then `$XDG_CONFIG_HOME/cursor`, then `$HOME/.cursor`, reading the launch environment before rune's own, and joins a relative directory to the repository, which is the child's working directory, so the check reads the same file the child reads. `prepare_clean_state` returns the configuration error without `CURSOR_API_KEY`. `keychain_hint` reads the Keychain signatures from stderr.
- `src/cli/surface/mod.rs`: the variant, `from_tool("cursor")`, the name, the table dispatch, the clean-state and process-request match cases, and the invoke dispatch. `refuse_unsupported_mode` refuses answer-only for Cursor beside codex, grok, and agy. `session_name_flag` is `None`. The filter uses `drop_whole`, because Cursor has no generic config channel, and passes its result through `keep_allowed`. `SurfaceFailure::hint` falls back to `cursor::keychain_hint` after the shared sandbox hints, so any tool whose stderr shows the signature gets it. `check_access` dispatches the access check.
- `src/cli/run/mod.rs`: `check_access` runs after the clean state is prepared and before the workspace exists, so a refusal is a configuration error with exit 125 and nothing started. The run strips the `--model` pair the launch generated, because it passes the model itself. The help text names Cursor.
- `src/cli/launch/mod.rs`: `cursor` in `KNOWN_TOOLS`, and `default_binary(name)`, which maps `cursor` to `cursor-agent`. Both `resolve_tool` and `list_tools` call it, so the list cannot disagree with the launch. `BUILT_IN_PROFILES` holds `fable@cursor`, which selects the built-in route `fable-cursor` (`claude-fable-5-1-high`, context 1,000,000). Cursor needs this table because it names each Fable effort level as its own id, so no tool-neutral `fable` route can serve it. `resolve_profile` checks the config first, then this table, and `profile_names` merges both for the missing-profile error and the tool list. The built-in routes move into one `BUILT_IN_ROUTES` table, which both the lookup and the unknown-route error read. `model_args` puts `--model <id>` in front of the profile arguments and records the pair in `ResolvedLaunch::model_args`.
- `src/cli/queue/mod.rs`: Cursor has no queue, so its messages go to the postbox like claude, agy, grok, and opencode.
- `src/cli/launch/mod.rs`, refusal: `refuse_url_credentials` runs in `resolve_with_config` after the profile environment is applied and before the argv is built. It collects a `CredentialPlace` for each raw argument, each string of a Codex `-c` value as TOML (`assignment_strings`) and of a Claude settings object as JSON (`settings_strings`), each value the route sets except a proxy variable (`is_proxy_env_key`), the plan's base URL, and the inherited base URL variable the child would read when the route sets none. A place is an endpoint, where a user name alone refuses, unless it is a route variable other than the tool's base URL variable. `url_userinfo` decides: `scheme_starts` yields every offset where a run of scheme characters ends at `:`, `parse_url_candidate` hands the text from there to `url::Url::parse`, whole, else cut at its first whitespace, and `url_credential` reads the parser's password, else its user name. The `url` crate implements the WHATWG URL Standard, so it reads `https:\\u:p@h`, `https:/u:p@h`, `https:///u:p@h`, `https:u:p@h`, and a tab before the `@` as Node's `new URL()` does, and no slash rule is written here. `credential_source` names where the tool reads its credential: the family's credential keys for claude and codex, `CURSOR_API_KEY`, and the grok key map. The message never repeats the URL.
- `src/cli/launch/mod.rs`, redaction: `url_query_secrets` takes from each URL the credential-named query values as written and percent-decoded. `is_credential_query_name` splits the parameter name on `_`, `-`, and camelCase boundaries (`camel_case_words`) and matches each word whole against `CREDENTIAL_QUERY_WORDS`, so `accessToken`, `apiToken`, and `clientSecret` are credentials and `keyword` and `maxTokens` are not. `redact_one_url` hides every credential-named parameter. `split_at_urls` ends a URL at whitespace, or at the quote that closes the one opened before its scheme, so a `'` inside a proxy password stays in the URL and a JSON or TOML string keeps its closing quote. `redact_argument` parses a `key=value` part as TOML once: a credential-named key or value hides the value whole, else `redact_toml_urls` hides the URLs in the decoded string and writes it back as a TOML string, or hides a table or array whole, so a TOML-escaped query name (`\u0074oken`) is read as codex reads it. `redact_output` is the one output function: the known values of eight characters or more, then the URL pass. `redact_output_json` applies it to every string in the plan object. `ResolvedLaunch::known_secrets` builds the launcher's set: the credential-named values, `proxy_credentials` of the effective and the inherited environment (the password, else the user name, of each proxy URL, as the parser serializes it and percent-decoded), the query secrets of each argument and, for codex, of each decoded `-c` string. `child_secrets` builds the runner's from the same proxy credentials, the effective environment, the inherited credential-named variables, the structured arguments, and the inherited base URL variable the selected tool reads. Neither reads every inherited variable.

The argument list for a run is `-p --output-format json --workspace <repo> --trust`, then `--mode ask` or `--force --sandbox enabled`, then `--model <id>` when a model is set, then the kept profile arguments. For a clean run the process request sets `HOME` to the clean root and `CURSOR_CONFIG_DIR` to `<root>/.cursor`. The key stays in the environment. `has_api_key` checks the launch environment, which holds profile `env` values, before rune's own, because the child gets the launch environment last.

## Decisions

Rune never passes a credential inside a URL. Three rounds of encoding fixes in the redaction did not converge: a `'` in a password ended the URL early, a Node URL parser rewrote the password in a form the scan did not hold, and a Base64 pair added one more form. Each form was one more way to leak. The launch refuses a URL that carries a password, in every place it passes, and the refusal names the variable or key file the tool reads its credential from. The userinfo forms, the WHATWG and Base64 variants, and the user-only redaction path are removed with the need for them.

The parser decides. The first refusal found an `@` after a `://`, and missed `https:\\u:p@h`, `https:/u:p@h`, `https:///u:p@h`, `https:u:p@h`, and a tab before the `@`, all of which Node's `new URL()` reads with a user and a password. A hand-written rule would chase the WHATWG special-scheme cases one at a time. The `url` crate implements that standard, so the candidate found by its scheme goes to the crate and the crate's user name and password answer. A user name alone refuses only where the tool reads an endpoint: `DATABASE_URL=postgres://postgres@localhost/app` names a role, not a secret, and refusing it stopped a route for no gain. A proxy variable passes whole, because the child needs its credential to reach the network, and the known values hide it instead.

The redaction set reads only the environment the route reads. Scanning every inherited variable blanked `postgres`, `anonymous`, and other ordinary words from a reply when `DATABASE_URL` or `FTP_URL` named a user. The set holds the credential-named variables, the route's own values, and the base URL variable the selected tool reads.

Every output passes `redact_output`: the dry run text and JSON, the reply, the check report, and a refusal. The dry run no longer has a redaction path of its own, which printed a bare-token URL and a TOML-escaped Codex URL whole. One exception stays: a failure tail and the harness's stderr pass the structural pass too (`redact_text`), because a failing harness prints a value beside its name that the run never knew. That pass does not fit an answer: it turned `Primary key: user_id` into `Primary key: <redacted>`.

## Commands

| Role | Command |
| --- | --- |
| The runner starts a read-only Cursor seat | `cursor-agent -p --output-format json --workspace <repo> --trust --mode ask [--model <id>]` |
| The runner starts a workspace-write Cursor seat | `cursor-agent -p --output-format json --workspace <repo> --trust --force --sandbox enabled [--model <id>]` |
| The launcher starts Cursor | `cursor-agent [--model <id>] <profile args> <native args>` |
| The runner reads Cursor's saved approval mode | `$CURSOR_CONFIG_DIR/cli-config.json`, else `$XDG_CONFIG_HOME/cursor/cli-config.json`, else `~/.cursor/cli-config.json` |

## Risks

- **A new Cursor flag widens access.** The allow-list covers it: a profile keeps only the endpoint flag, so a new or unlisted flag never reaches the tool. The owned table stays for its value-aware warnings. The bypass table test has Cursor rows for owned and unlisted flags.
- **Ask mode is a CLI rule and no kernel boundary.** `cursor-agent` enforces it: every live read-only run of the first version that asked for a file wrote nothing, including one under a copied `unrestricted` config (2026-10-01). The model still lists Shell, Write, and StrReplace as its tools under ask mode. `check_access` refuses `unrestricted` as defense in depth. A read-only run cannot add a kernel sandbox, because `--sandbox enabled` without `--force` still asks for approval, and print mode cannot answer. The ADR records this limit.
- **The JSON shape changes.** Cursor does not document `usage`. The parser makes `usage`, `subtype`, and `is_error` optional. A last top-level record without `type: result` fails as a harness failure, and so does output that is not JSON. An empty or missing `result` fails as an empty reply.
- **The Keychain hint misfires.** The hint matches the trust-settings text, or "Authentication required" only while `SANDBOX_RUNTIME` is set. Outside the sandbox, a real missing login gets no hint.
- **A clean home drops the owner's Cursor hooks.** `~/.cursor/hooks` holds the owner's shell guard. A clean run loses it by design, like every other clean run. Workspace-write clean runs rely on Cursor's own sandbox.
- **The port was not run against a live `cursor-agent`.** Every flag and the JSON shape come from the first version, checked on 2026-09-29. The tests use a recording fake. A live run outside the sandbox is the open verification task.
- **`cli-config.json` may hold an endpoint URL.** Cursor's documentation could not be fetched from the review session, because the sandbox denied the network, so no endpoint key in that file is known. The runner reads only `approvalMode` from it and scans none of its values for a URL credential. When a live check finds such a key, `check_access` is the place to read its URL and add it to `child_secrets`.
- **A harness echoes a URL password rune never passed.** `redact_one_url` still hides a password and the credential-named query values of any URL in an output, so a URL the tool reads from its own files loses them when it is echoed. The known-value pass cannot hold such a password, because the run never saw it.
- **A proxy credential shorter than eight characters prints.** The known-value pass skips a value under `SUBSTRING_MIN_CHARS`, so a short proxy password is hidden only by the URL pass, which needs the URL printed whole. A harness that echoes the password alone leaks it. The `url` crate serializes a password percent-encoded, so both that form and the decoded one are known values.
- **The quote rule reads one character of context.** `split_at_urls` takes the quote before a scheme as the one that closes the URL. A password that holds the same quote character ends the URL early in a JSON or TOML string, where that character is escaped anyway, and in free text a `'` password is kept whole.
